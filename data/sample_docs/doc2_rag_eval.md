# RAG 评测与调试

RAG 系统做出来之后，最常见的困境是"效果说不清"：换了 embedding 模型、调了切片大小，到底是变好了还是变坏了，全靠肉眼看几个例子猜。这就是 RAG 评测要解决的问题。

最基础的两个检索层指标是 HitRate 和 MRR。HitRate@k 表示在准备好的黄金问答集上，正确文档出现在每次检索结果前 k 名的问题占比。比如 HitRate@5 等于 0.8，意味着 80% 的问题都能在前 5 个结果里找到正确文档。MRR 是平均倒数排名，衡量正确文档排得有多靠前：排第 1 名得 1 分，排第 2 名得 0.5 分，越靠后得分越低。MRR 高说明结果不仅"找得到"，而且"排得靠前"。

答案层还有一个常用指标叫 faithfulness（忠实度），衡量生成的答案是否忠于检索到的上下文，而不是模型自己编造。它通常需要再调用一个大模型作为裁判来打分。

为什么要做切片对比实验？因为切片策略是 RAG 里最容易被拍脑袋决定的环节。正确做法是准备一份黄金问答集，固定其他条件，只切换片策略，然后对比 HitRate 和 MRR 的变化。如果定长 256 的 HitRate@5 是 0.6，而句子切片是 0.8，结论就非常明确。这样每次调参都留下记录，实验可复现，团队里任何人接手都能看懂上一步做了什么、为什么这么做。
