# RAG 基础原理

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把私有知识接入大语言模型的常用架构。它的核心思想是：在把问题交给大模型生成答案之前，先从外部知识库里检索出相关片段，拼到提示词里，让模型"开卷考试"。

一个完整的 RAG 系统通常包含五个步骤。第一步是文档加载，把 PDF、Markdown、网页等原始资料读成纯文本。第二步是文档切片，把长文本切成一个个适合检索的小块。第三步是嵌入，用 embedding 模型把每个分片转成向量。第四步是检索，用户提问时把问题也转成向量，在向量库里找到最相似的若干个分片。第五步是生成，把检索到的分片连同问题一起交给大模型，生成最终答案。

切片策略对最终效果影响很大。定长切片按字符数切分，实现简单但可能把一个完整句子拦腰切断。句子切片先按句号、问号等标点断句，再把短句拼起来，语义更完整。切片时通常会设置重叠窗口 overlap，让相邻分片共享一小段文本。overlap 的作用是避免关键信息恰好落在两个分片的边界上被割裂，从而提升召回率。代价是分片数量和存储成本会上升。

检索阶段常用的相似度计算方法是余弦相似度。它衡量两个向量方向的接近程度，取值在 -1 到 1 之间，越接近 1 表示两个向量越相似。检索时一般取相似度最高的 top_k 个分片交给后续流程。为了提升精度，很多系统还会在向量检索之后加一步重排，用更精细的模型对候选分片重新打分排序。
